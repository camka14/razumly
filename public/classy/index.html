Text description of the demo
  1. A Support request triage classifier is configured with Bug, Feature, Task and Question categories and a 75% confidence threshold.
  2. Two fictional Jira requests are classified as Bug and Feature, and the classifier revision is published.
  3. The saved decisions show their confidence values, category probabilities and classifier definition. The published revision is selected in a native Jira Automation rule.
  4. The rule checks that the decision status is classified and the category is Bug before adding an engineering label and a comment containing the decision output.
  5. The rule runs on a fictional bug report. The issue receives the engineering label and decision comment, and the Automation audit shows Success.

A workbench and two native actions

Define a question, category matching criteria and a confidence threshold. Try authorized Jira issue text or supplied text in the Classy workbench, then inspect the selected category, confidence and probability distribution.

Publish a revision for site-wide use in Classy: Classify issue or Classy: Classify text. Classy returns a decision; your Jira Automation rule controls any field edits, labels, assignments or notifications.

Unclear and below-threshold decisions are marked Review. Confidence is a model estimate, not a guarantee of correctness. Keep a separate review path and require status = classified before category-specific writes.
